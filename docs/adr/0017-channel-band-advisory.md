# ADR-0017: バンド・チャネル選択助言

**Date**: 2026-05-13
**Status**: Accepted

## Context

トライバンド (2.4/5/6GHz) 環境では、どのバンド・どの AP に接続すべきかが性能を大きく左右する。arXiv / 学術研究から以下が判明:

1. **6GHz 干渉測定** (Dogan-Tusha et al., ACM WiNTECH 2023, arXiv 2307.00235)
   - 6GHz 帯は 59 の新規 20MHz チャネルで輻輳を緩和
   - ただし建物侵入損失 (BEL) が大きく、壁越しでは減衰が著しい

2. **トライバンドチャネル選択** (ScienceDirect 2024)
   - 不適切なバンド管理が頻繁な干渉とネットワーク問題を招く

3. **バンドステアリング** (運用ベストプラクティス)
   - 高密度環境では 20MHz 幅が非重複チャネル数を最大化し、40/80MHz より総容量で優れる

4. **学習ベースチャネルアクセス** (arXiv 2511.10143)
   - OBSS (Overlapping BSS) 負荷が重複する中でプライマリチャネル選択が重要

## Decision

### `ChannelAdvisorService` 新設

クライアント視点で「どのバンド/AP を選ぶべきか」を助言する。チャネル変更は行わず、接続先選択の助言のみ。

| メソッド | 機能 |
|---|---|
| `RecommendBand()` | 同一 SSID の複数バンドから最適を推奨 |
| `ScoreBandChoice()` | バンド選択スコア (信号強度×バンド特性) |
| `IsNonOverlappingChannel()` | 2.4GHz の 1/6/11 判定 |
| `AdviseChannelWidth()` | 密度に応じたチャネル幅助言 |
| `EstimateCongestion()` | 同一チャネル AP 数から混雑度推定 |
| `DescribeBandChoice()` | 人間語の助言 |

### バンド選択ロジック

基礎スコア (空き具合): 6GHz(100) > 5GHz(70) > 2.4GHz(40)
到達性ペナルティ: 6GHz は弱信号で大きく減点 (BEL が大きい)

→ 強信号では 6GHz、壁越しの弱信号では 5GHz を推奨するという研究知見を反映。

### チャネル幅ロジック

- 高密度 (近隣AP≥10) で 80MHz 以上 → 20MHz 推奨 (非重複チャネル最大化)
- 低密度で 20MHz → 80MHz 推奨 (個別スループット最大化)

## Consequences

- ユーザーはトライバンドルーターで最適なバンドを選べる
- 2.4GHz の重複チャネル干渉を警告できる
- 高密度環境 (オフィス/イベント会場) でのチャネル幅最適化を助言できる
- プラットフォーム層で BSS Load IE (チャネル使用率) を取得すれば、
  より正確な混雑度推定が可能になる将来拡張がある
- `RoamingAdvisoryService` (ADR-0016) / `SignalQualityPredictor` (ADR-0015) と
  組み合わせ、総合的な「最適 AP 選択」エンジンを構成できる
